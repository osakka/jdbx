# Bug Fixes - January 23, 2025

## Overview
This document describes the bug fixes implemented on January 23, 2025, addressing critical issues with document deletion and query filtering in the JSONdb server.

## Fixed Issues

### 1. Document Deletion API Returning "Collection not found" 

**Problem**: DELETE requests to `/api/collections/{collection}/documents/{id}` were incorrectly handled by the collection drop handler, resulting in "Collection not found" errors.

**Root Cause**: The API route for collection drop (`/api/collections/`, HTTP_DELETE) was matching document deletion paths before the document delete handler could process them.

**Solution**: Modified the collection drop handler in `src/components/core/api.c` to detect document paths and delegate to the document delete handler:

```c
/* Check if this is actually a document operation path */
if (strstr(name, "/documents/") != NULL) {
    return api_handle_document_delete(ctx, request);
}
```

**Files Modified**:
- `src/components/core/api.c` - Added path detection logic to `api_handle_collection_drop()`

### 2. Query Filtering Not Working with URL Parameters

**Problem**: Query parameters passed in the URL (e.g., `?name=Test`) were not being applied to filter results. The API was trying to parse URL query strings as JSON, which failed.

**Root Cause**: URL query parameters use `key=value&key2=value2` format, not JSON. The code was attempting to parse this format with `json_parse()`, which expected valid JSON.

**Solution**: Implemented a URL query parameter parser that converts URL-encoded parameters to a JSON object:

```c
static json_value_t* parse_url_query_to_json(const char* query_string) {
    // Parses key=value pairs separated by &
    // URL-decodes values (handles %XX and + encoding)
    // Returns a JSON object with string values
}
```

**Limitations**: URL parameters are always parsed as strings. For exact type matching (numbers, booleans), use JSON body queries instead.

**Files Modified**:
- `src/components/core/api.c` - Added `parse_url_query_to_json()` function and updated `api_handle_documents_query()`

## Testing Results

All fixes have been thoroughly tested with the following scenarios:

1. **Document Deletion**:
   - ✅ Deleting existing document returns 204 No Content
   - ✅ Deleting non-existent document returns 404 Not Found
   - ✅ Deleted documents are removed from the database

2. **Query Filtering**:
   - ✅ JSON body queries work with proper type matching
   - ✅ URL parameter queries work for string matching
   - ✅ Empty queries return all documents
   - ✅ Queries with no matches return empty results

## API Usage Examples

### Document Deletion
```bash
# Delete a specific document
curl -X DELETE http://localhost:5000/api/collections/users/documents/doc-123 \
  -H "Authorization: Bearer <token>"
```

### Query Filtering

**Using JSON body (supports all types):**
```bash
curl -X GET http://localhost:5000/api/collections/users/documents \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"age": 25, "active": true}'
```

**Using URL parameters (string matching only):**
```bash
curl -X GET "http://localhost:5000/api/collections/users/documents?name=John%20Doe" \
  -H "Authorization: Bearer <token>"
```

## Implementation Details

### Persistence Thread Initialization
During testing, we also discovered and fixed an issue where the persistence thread wasn't surviving daemonization. This was resolved by moving persistence thread initialization to after the daemonization process.

### JSON Serialization Fix
Fixed a missing case in `json_stringify()` for `JSON_INTEGER` type that was causing query results to fail serialization.
